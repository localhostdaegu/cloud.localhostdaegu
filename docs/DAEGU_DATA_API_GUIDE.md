## 0. 전제와 원칙

- Metabole(서울) 파이프라인을 **지역 어댑터 교체 방식**으로 재사용한다. 서울 전용 소스는 3개뿐이고 나머지는 전국 데이터라 필터만 바꾼다.
- 매출 주지표는 서울과 동일하게 **개폐업률·점포수(인허가 API)** 로 간다. 대구 공개 추정매출은 없고, 카드매출은 DIP 센터 안에서만 쓸 수 있으므로 **프로토타입 제외·제안서 로드맵 기재**.
- 발급 키는 전부 `backend/.env` 재사용. **신규 발급이 필요한 키는 0개** (전부 기존 키 + 활용신청 추가만).
- 수집 서버 국내 IP 원칙 유지 (기존 §6-1).

대구는 2023-07 군위군 편입으로 **9개 구·군**. 프로토타입은 8개(군위군 제외)로 시작해도 무방.

| 중구 | 27110 | 3410000 | 동성로·서문시장·약령시 |
| 동구 | 27140 | 3420000 | 동대구역·평화시장 닭똥집골목 |

## 2. 공공데이터포털 (data.go.kr) — 키 `DATA_GO_KR_API_KEY`

### 2-1. 기존 활용신청 완료 → 대구 파라미터로 즉시 호출

#### ✅ 지방행정 인허가 7업종 (P0 · 개폐업 시계열의 진실 소스)

```
GET https://apis.data.go.kr/1741000/{slug}/{info|history}
  serviceKey, pageNo, numOfRows(max 100), returnType=json
  cond[OPN_ATMY_GRP_CD::EQ]=3410000        ← 구·군별 루프 (§1)
  cond[LCPMT_YMD::GTE]=20170101            ← 인허가일자
  cond[DAT_UPDT_PNT::GTE]=...              ← 증분 커서
  /history: cond[BASE_DATE::EQ]=YYYYMMDD   ← 특정 시점 스냅샷
```

| 업종 | slug | 데이터셋 ID |
|---|---|---|
| 일반음식점 | `general_restaurants` | 15154916 |
| 휴게음식점 | `rest_cafes` | 15154921 |
| 미용업 | `beauty_salons` | 15154918 |
| 체력단련장업 | `fitness_centers` | 15155077 |
| 당구장업 | `billiard_halls` | 15155011 |
| 노래연습장업 | `karaoke_rooms` | 15155135 |
| PC방 | `pc_bangs` | 15154951 |

- 응답 주요 컬럼: `BPLC_NM`, `LCPMT_YMD`, `CLSBIZ_YMD`, `DTL_SALS_STTS_NM`, `MNG_NO`, `ROAD_NM_ADDR`, `CRD_INFO_X/Y`, `BZSTAT_SE_NM`
- 서울 대비 변경점: `OPN_ATMY_GRP_CD` 값 목록만 교체. 수집기 코드는 그대로.
- 초기 적재: 구·군 8 × 업종 7 × 페이지네이션. 대구는 서울의 약 1/4 규모라 1일 내 완료 예상.

#### ✅ 소진공 상가(상권)정보 (15012005) — 현재 경쟁밀도·좌표

- 시도코드 대구(`27`) 또는 시군구코드 `27110…27720` 파라미터로 조회 `[파라미터명 확인]`
- 역할 분담 유지: 상가정보 = 현재 스냅샷·좌표 / 인허가 = 시계열
- 분기 전체 CSV(15083033)에서 대구 필터해 시점 스냅샷 병행 적재

#### ✅ 국토부 상업업무용 부동산 매매 실거래가 (15126463)

```
LAWD_CD = 27110 | 27140 | 27170 | 27200 | 27230 | 27260 | 27290 | 27710 | 27720
DEAL_YMD = 201701 … 202608   (월 루프)
```
- 최근 1~2개월 미완결 주의(신고기한 30일). 서울 수집기 그대로, 코드 리스트만 교체.

#### ✅ 보조금24 (15113968), ✅ 거리두기 현황 (15098772)
- 그대로 사용. 거리두기는 전국 단계 + 2020.2~11 수기 테이블(기존 §4) 재사용. 대구는 2020.2~3 1차 대유행 중심지였으므로 **대구 특별 조치 기간을 더미변수로 추가**하면 지역성 가점 `[보도자료 수기]`.

### 6-2. 반출 집계 테이블 설계 (센터 안에서 실행할 스크립트를 미리 작성)

```
sales_monthly        행정동코드 × 업종중분류 × 월 × [amt, cnt, card_issuer]
                     ← 삼성(24~25) ∪ KB(20~21.07) ∪ 현대(17~22.08, BLOCK→행정동 via 8-1)
                     ※ 카드사별 절대값 연결 불가 → card_issuer 구간별 지수화 (R-ONE 빈티지 방식)
                     ※ 공백 2022.09~2023.12

service_pop_monthly  행정동코드 × 월 × [resident, worker, visitor] × 연령대합
                     ← 5-2-2 sex_age_pop 일별 → 월평균

delivery_share       행정동 × 업종 × 월 × [order_cnt, shop_cnt]
                     ← 12-2 주문 ⋈ 가맹점정보
```

- 스크립트 위치: `scripts/dip_center/` — pandas 단독 실행 가능하게(센터 PC 환경 미지). 입력 파일명은 설명서의 실제 파일명 사용(`DIP_2401_2412_FF`, `daegu_service_pcell_sex_age_pop_YYYYMM.CSV` 등).
- 반출물은 집계값이므로 개인정보 이슈 없음. 반출 승인 절차는 센터 확인 `[확인]`.

### 6-3. 어댑터 슬롯

Metabole Strategy 패턴에 `SalesSource`, `PopulationSource` 포트를 두고 프로토타입에서는 `NullSalesSource`(개폐업률로 대체) / `ProxyPopulationSource`(주민등록+승하차) 구현체를 꽂는다. 본선 전 `DipSalesSource` / `DipPopulationSource` 로 교체. 제안서에는 이 구조도를 "2단계 데이터 확장" 으로 기재.

## 9. 열린 질문 (팀 결정)

1. 군위군 포함 여부 — 프로토타입은 8개 구·군 권장 (데이터 희소·코드 미확정)
2. 생활인구 프록시를 "주민등록 + 승하차" 로 갈지, s4u 수기 샘플까지 화면에 노출할지 (노출 시 "센터 반출 전 임시값" 라벨 필수)
3. 블록체인 요소: 리포트 해시 앵커링 API 구현 vs 제안서 로드맵만 — D-2 진행 상황 보고 결정
4. 서비스명: Metabole 대구판을 별도 명칭으로 낼지 (참가서약서 타 대회 출품 조항 확인 후)
5. R-ONE 대구 상권이 서울처럼 80여 개 수준인지, 훨씬 적으면 임대료 축을 구 단위 평균으로 낮출지
