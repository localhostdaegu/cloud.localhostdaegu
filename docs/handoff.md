우선 해결할 사항:

1. **연도 불일치:** (9/18 부분 해소 — 요약 카드·위험도 기본 연도를 데이터 기준 마지막 완결 연도(현재 2025)로, 지도 기본 연도도 2025·2026은 "(집계 중)" 표시. AI 분석에 지도 선택 연도 전달은 아직 안 함) 지도는 선택 연도를 전달하지만 사이드패널 요약은 `backend/apps/master/adapter/outbound/gateways/metric_summary_gateway.py`의 `_LATEST_YEAR = 2026`을 사용한다. 위험도 조회와 AI 분석에도 지도 선택 연도가 전달되지 않는다. 지도·요약·리포트의 기준 연도와 집계 기준일을 통일한다. 우선 2025년을 기본 비교연도로 두고 2026년 연중 자료를 구분하는 방안 검토.
2. **‘성장률’ 명칭:** 실제 산식은 `(개업 수 - 폐업 수) / 전년 말 점포 수`. 매출 성장으로 오해되지 않도록 ‘점포 증감률’로 바꾸고 분모·기간·개폐업 건수를 함께 표시한다. 폐업률도 개별 가게의 실패 확률로 설명하지 않는다.
3. **카페 분류·단기 개폐업:** 성내2동(`2711057500`)의 2025년 카페 폐업률은 약 95.8%(폐업 182건 / 전년 말 190개). 폐업 182건 중 **137건은 개업 후 30일 이내 종료** 기록이다. `rest_cafes` 원천 전체를 `cafe`로 묶고 있어 단기 행사·팝업 등의 혼입 가능성이 있다. **원인은 미확정**이며 원천의 세부 업종·영업 형태를 확인해야 한다. 30일 이하를 일괄 삭제하지 말고 분류 근거를 확보한 뒤 집계를 비교한다.
4. **위험점수의 의미:** 현재 `risk_interactor.py`는 폐업률·점포 수·점포 증감률의 상대 순위를 사용한다(가중치 0.4/0.4/0.2). ‘경쟁밀도’는 면적·인구·반경으로 나눈 값이 아니며 점포 순증가도 위험점수를 높인다. 경쟁 압력 지표라는 가설을 검증하기 전에는 ‘진입 양호/고위험’을 확정 판단처럼 제시하지 않는다. 점수는 실패 확률이 아니다.
5. **재무 입력을 건너뛰는 동선:** 지도에서 주 버튼 ‘AI 분석’으로 이동하면 지역·업종만 전달된다. 재무 입력이 없으면 `FundingAgent`는 부족 자금 0원 기준으로 상품을 매칭한다. 예산·비용 확인을 먼저 거치도록 주 동선을 재검토한다.
6. **AI 단계의 실제 기능:** `ShockAgent`는 현재 관련 뉴스 검색이며 정량적인 충격 영향 계산이 아니다. ‘오케스트레이터’와 도구명은 내부 구현 용어다. 사용자에게는 수행 중인 작업을 설명하고, 실제 재무 시나리오 계산을 핵심 단계로 드러낸다.

### 0-2-1. 9/18 허브 문서 정합성 작업 중 코드 대조로 확인된 사실 (컨트롤러 재검증 완료)

### 0-2-4. 고립 테이블 2건 — 고치지 않기로 한 근거 (2026-09-18 실측)

`backend/CLAUDE.md` §13은 고립 테이블을 금지하지만, 두 건은 **엣지를 만드는 쪽이 더 나쁘다**고 판단해 그대로 뒀다. 대신 `tests/test_schema_isolation.py`로 **예외 2건을 이름과 근거로 고정**했다 — 새 고립 테이블이 생기면(진짜 설계 오류) 테스트가 실패하고, 예외가 해소됐는데 목록에 남아 있어도 실패한다. 산문으로만 적어 두면 다음 사람이 규칙을 어긴 줄 모르고 지나간다.

- **`interest_rate`** — 전국 단위 금리 시계열이라 행정동·업종 어느 허브 키에도 함수 종속되지 않는다. `region`을 붙이면 144행정동 × 기간만큼 같은 값을 복제하게 되어 **3NF 위반**이다.

### 0-4. 다음 작업 — 센터 확인부터 작은 집계 확보까지

아래는 후속 작업 제안이며 **센터 문의·예약·데이터 확보·구현은 아직 수행하지 않았다.** 외부 담당자에게 메시지를 보내는 작업은 사용자 지시를 받은 뒤 진행한다.

1. **확인할 조건을 먼저 정리한다.** 이용 신청·분석실 예약·반입 코드 실행 환경·반출 심사 소요시간, 허용 집계 단위·소수 표본 제한, 출처 표기, 서비스 DB 저장·웹 공개·시연 가능 범위를 확인한다. 특히 삼성카드의 별도 반출 조건과 SKT 세부 파일의 최신 제공월을 확인한다. 답변과 승인 범위를 문서로 남긴다.
2. **대표 행정동 몇 곳과 한 업종으로 범위를 좁힌다.** 인허가 업종 분류부터 검증한 후 지역·업종을 선정한다. 2024~2025년 삼성카드와 같은 기간 생활인구의 조합을 우선 검토하되, 이용·반출 조건 확인 전에는 확보를 전제하지 않는다.
3. **집계 명세를 센터와 확인한 뒤 추출한다.** 후보는 아래 표와 같다. 원천 업종을 내부 업종으로 매핑하고 행정동 코드·경계 기준을 맞춘다. 카드사별 표본·포괄 범위가 다르므로 서로 다른 카드사의 금액을 단순 합산하거나 이어 붙여 성장률을 만들지 않는다.
4. **허용된 결과만 적재하고 연결을 검증한다.** 출처·집계 기간·추출일·단위·집계 방법·이용 조건을 함께 기록한다. 원천과 반출 결과의 합계 대조, 중복·결측, 행정동·업종 매핑률을 확인한다. 화면과 AI 리포트가 같은 기준을 사용하고, 데이터 없는 지역·기간은 ‘없음’으로 표시하는지 검증한다.

| 집계 후보(미구현) | 용도·주의점 |
|---|---|
| 행정동 × 업종 × 월 × 카드사 → 소비금액·결제건수 | 점포 증감에 비해 소비도 늘어나는지 비교. 카드사 집계금액을 전체 시장 매출이나 개별 가게 예상 매출로 표시하지 않음 |
| 행정동 × 월 → 거주·직장·방문 인구의 평균 등 | 수요의 구성 비교. 시간대별 인구를 단순 합산해 고유 방문객 수로 표현하지 않고 집계 정의를 확인 |
| 행정동 × 시간대 → 생활인구 분포 | 영업시간·고객층 가설 보완. 기준 기간과 평일·주말 구분 등은 허용 범위 확인 후 결정 |

마감 전 이용·반출이 확정되지 않으면 **현재 공공데이터와 사용자 입력만으로 검증 가능한 데모를 완성**하고 센터 데이터는 후속 확장으로 명시한다. 대표값·샘플을 실제 확보한 데이터처럼 표시하지 않는다.

### 0-5. 제품 방향과 마감 전 우선순위 — 제안, 미구현

기획서의 예비창업자 대상을 유지할 때 권장하는 중심 질문은 **‘이 창업 계획으로 계약하기 전에 무엇을 바꿔야 할까?’**이다. 사용자 대상 변경이나 아래 동선 개편을 확정·구현한 상태는 아니다.

권장 동선: 지역·업종·자기자본 → 주변 개폐업 현황 → 보증금·월세·투자비·예상 매출 확인 → 손익분기 매출·자금 여유 계산 → 비용 조건 변경·비교 → 필요한 금융 상담 준비. 지도는 입지 탐색·근거 확인 역할을 맡고, AI는 계산 결과와 근거를 설명한다.

- [ ] **P0 데이터 검증:** 대표 업종의 단기 개폐업·분류를 검증하고 폐업률·점포 증감률의 분모·기간을 표시한다. 근거가 부족한 위험 판정은 완화한다.
- [ ] **P0 기간 일치:** (9/18 기본 연도 2025 통일 완료, AI 분석 연도 전달은 남음) 지도·요약·AI 분석의 연도와 기준일을 통일한다. 다른 연도를 선택해도 모든 결과가 같은 기준을 유지하는지 확인한다.
- [ ] **P0 자금 점검 동선:** ‘내 예산으로 창업 계획 점검’을 주 행동으로 두는 방안을 검토한다. 재무 입력 없이 생성한 상품 목록을 개인별 자금계획에 맞춘 결과로 설명하지 않는다.
- [ ] **P0 AI 표시 개선:** ‘입력 확인 → 주변 현황 확인 → 필요 자금·손익분기 매출 계산 → 상담 후보 확인 → 결과 정리’처럼 실제 수행 작업으로 표시한다. 뉴스 검색은 ‘관련 뉴스·외부 변화 확인’으로 설명한다. 금리·매출 변화 영향은 재무 엔진의 실제 계산과 연결할 때 제시한다.
- [ ] **P0 계산 가정 표시:** 예상 매출은 사용자 가정이다. 현재 부족 자금은 초기 투자비 + 6개월 고정비 확보 기준이며, 비관·기준·낙관 매출 배수도 가정임을 표시한다. 자금 부족 시 투자비·월세 축소와 금융 상담을 함께 검토할 수 있게 한다.
- [ ] **P0 완주 시연:** 한 사람이 계획을 입력하고 결과를 이해한 뒤, 월세나 투자비 한 항목을 바꿔 계산 결과가 어떻게 달라지는지 확인하는 데모를 완성한다. 센터 데이터 확보는 이 데모 완성의 필수 선행조건으로 두지 않는다.
- [ ] **문서 정합성:** 기획서의 위험도 산식·센터 확보 일정과 실제 구현의 차이를 정리한다. 공모전 정리의 ‘AI+블록체인 모두 필수’, ‘코드 제출만 가능’도 수정한다. 확인한 [공고문 원문](https://hyds.hanyang.ac.kr/front/notice/unN/file-load?fileId=3054&id=1811)에는 동시 구현 필수 조건이 없고 제출물은 프로토타입 **또는 구현·시연 영상**으로 되어 있다.
