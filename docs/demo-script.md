# 시연 대본 (2026-09-18 작성)

목표 길이 **3분**. 모든 수치는 `backend/apps/finance/domain/engine.py`로 검산한 값이다 — 대본대로 입력하면 화면에 그대로 나온다.

## 0. 사전 준비

- [ ] 백엔드 8300 기동 (`GEMINI_API_KEY` 필요 — 리포트 장면에 쓴다)
- [ ] 프론트 3300 기동, `NEXT_PUBLIC_API_BASE=http://localhost:8300` (또는 배포 URL)
- [ ] 브라우저 세션 비우기 — `sessionStorage`에 이전 계획안이 남아 있으면 비교표가 먼저 떠서 흐름이 깨진다
- [ ] 리포트 생성이 **실측 11~16초**다. 녹화 시 이 구간을 배속 처리할지 미리 정한다

## 1. 문제 제기 (0:00~0:25)

> "창업 계산기에 희망대출 2,500만 원을 넣으면 대부분 이렇게 답합니다 — **부족액 0원, 자기자본으로 충분합니다.**
> 그런데 그 2,500만 원은 아직 빌리지 않은 돈입니다. 예비창업자는 '충분하다'는 화면을 보고 은행에 갈 이유를 잃습니다."

## 2. 진입과 자리 선택 (0:25~0:50)

- 홈에서 입력: **`중구에서 카페, 예산 4천만`** (실측: `district_code` 27110 · `industry_id` cafe · `budget_krw` 40,000,000 — **자기자본 4,000만원이 자동 프리필된다**)
- 지도로 이동 → **대신동** 폴리곤 클릭
- 사이드 패널에 개폐업·생존율 지표 노출

> "지도는 자리를 고르고 근거를 확인하는 곳입니다. 여기서 바로 AI 분석으로 가지 않습니다 —
> 재무 입력 없이 리포트를 만들면 비용을 0원으로 가정한 엉터리 상품 추천이 나오기 때문입니다."

- **주 버튼** `이 자리로 창업자금 사전상담 →` 클릭

## 3. 입력과 최초 계산 (0:50~1:30)

**창업 단계**
- 사업자등록을 하셨나요? → **아니오**
- 개업 예정일 → 임의 (예: 2026-11-01)
- 자금 필요일 → 임의 (예: 2026-10-15)

**비용·자금** (만원 단위로 입력)

| 항목 | 값 |
|---|---:|
| 보증금 | 2,000 |
| 인테리어 비용 | 2,000 |
| 설비 비용 | 1,000 |
| **월세** | **250** |
| 월 인건비 | 90 |
| 월 보험료 | 10 |
| 자기자본 | 4,000 *(홈 문장에서 자동 프리필 — 그대로 둔다)* |
| **희망 대출금** | **2,500** |
| 예상 월매출 | 800 |
| 원가율 / 수수료율 / 대출금리 | 57 / 3 / 4.8 |

`시뮬레이션 실행` → **최초안** 확정

| 화면에 나오는 값 | 금액 |
|---|---:|
| 손익분기 매출 | 900만원 |
| 총 준비자금 | 7,160만원 |
| **자기자본 외 조달 필요** | **3,160만원** |
| 희망대출 반영 후 남는 부족액 | 660만원 |

## 4. ★ 핵심 장면 — 조건을 바꾸면 부족액이 0원이 된다 (1:30~2:10)

- **월세만 250 → 100**으로 수정
- 수정 직후 경고 노출: *"아래 결과는 이전 입력 기준이에요"* — **선택 버튼이 잠긴다**

> "고치기만 하고 아직 계산하지 않았으니, 이전 결과로 상담 안을 고르지 못하게 막습니다."

- `시뮬레이션 실행` → **현재안**

| 화면에 나오는 값 | 금액 |
|---|---:|
| 손익분기 매출 | 525만원 |
| 총 준비자금 | 6,260만원 |
| **자기자본 외 조달 필요** | **2,260만원** |
| 희망대출 반영 후 남는 부족액 | **0원** |

> "부족액이 0원이 됐습니다. 기존 계산기라면 여기서 '자기자본으로 충분'이라고 말하고 끝납니다.
> 그런데 우리 화면은 **자기자본 외 조달 필요 2,260만 원**과 **미확보 희망대출 2,500만 원**을 함께 보여줍니다.
> 이게 은행에서 상담해야 할 실제 금액입니다."

- 비교표에서 바뀐 조건이 **`월세 250만원 → 100만원` 한 줄만** 표시되는 것을 보여준다

> "바뀌지 않은 조건을 변경점처럼 설명하지 않습니다."

- **변경 이유** 입력: `월세가 낮은 자리로 바꿨습니다`
- `현재안` 선택 상태 확인 → `이 안으로 상담 준비 →`

## 5. 상담자료 (2:10~2:50)

리포트 섹션이 순서대로 채워진다 — **상담할 계획 → 최초안과 현재안 → 재무 시뮬레이션 → 자금 후보 → 상담에서 확인할 것 → 지역 근거**

짚을 것 셋:

1. **비교표와 계산표는 AI가 만들지 않는다.** 코드가 계산한 값이고, AI는 변경 이유 설명과 상담 질문만 쓴다
2. **자금 후보** — iM뱅크 취급이 확인된 상품만 1군이다. 나머지는 "차선 후보 — iM뱅크 취급 미확인"으로 분리된다
   > "상품 12건의 공식 원문을 전부 대조했고, iM뱅크 취급이 확인된 건 3건입니다. 확인 안 된 걸 확인된 것처럼 보여주지 않습니다."
3. **상담에서 확인할 것** — 사용자가 '모름'이라고 답한 항목이 숫자 가정으로 바뀌지 않고 그대로 남는다

## 6. 마무리 (2:50~3:00)

- `상담자료 저장 (Markdown)` 클릭 → 파일 다운로드
- `iM뱅크 공식 상담 안내` 링크 노출

> "자료를 저장해 상담에 직접 지참합니다. 링크를 눌러도 은행에 자료가 전송되지 않습니다 — 제휴가 없기 때문이고, 화면에도 그렇게 적혀 있습니다."

---

## 하지 말 것

- **후보 3건이 뜨는 화면만 보여주지 않는다.** 12건 중 3건이고 나머지는 차선 후보로 분리돼 있다는 것이 이 서비스의 핵심이다. 분리 자체를 보여주는 편이 낫다
- **"iM뱅크와 연계했다"고 말하지 않는다.** 제휴는 없다. 공개된 공식 채널을 안내할 뿐이다
- **승인·한도·금리를 보장하는 표현을 쓰지 않는다**
- 블록체인 요소는 이번 범위에 없다. 질문받으면 "트랙 5.3 공식 예시에 블록체인 항목이 없어 상담 동선 완성을 택했다"고 답한다

## 예상 질문과 답

| 질문 | 답 |
|---|---|
| 은행과 실제로 연계했나요? | 아니요. 제휴 없이 공개된 공식 상담 경로만 안내합니다. 자료는 사용자가 지참합니다 |
| 상품 추천이 정확한가요? | 추천이 아니라 **상담 후보**입니다. 공식 원문에서 iM뱅크 취급 근거를 확인한 것만 1군으로 두고, 확인 못 한 조건은 "상담에서 확인할 것"에 남깁니다 |
| AI가 숫자를 지어내지 않나요? | 계산과 표는 전부 결정론 코드입니다. AI는 이미 계산된 값을 읽고 설명·질문만 씁니다. AI 생성이 실패해도 계산표는 남습니다 |
| 매출 예측은 어떻게 하나요? | **하지 않습니다.** 예상 월매출은 사용자가 입력한 가정이고, 그 사실을 상담자료의 "계산에 사용한 가정"에 적습니다 |
| 데이터는 실제인가요? | 인허가 개폐업 161,115건, 정책자금 공고 1,641건, 금리·임대료 실적재입니다. 카드 매출·생활인구는 미확보이며 그렇게 표기합니다 |
