# 금융상품 상담 메타데이터 원문 대조 기록 (2026-09-18)

전환계획 §10-3의 기록 항목을 따른다. **공식 원문에서 확인한 것만 적는다.**
확인하지 못한 항목은 빈칸이 아니라 "미확인"으로 남긴다 — 추정으로 채우면 상담 자리에서 사용자가 틀린 안내를 들고 가게 된다.

## 0. 이번 대조의 범위와 한계

> **2026-09-18 3차 갱신 — 12건 전부 대조 완료.** 재단 TLS 문제 해결(§0) 후 재단 4건, 이어서 나머지 5건까지 원문을 확인했다. 등급 분포: `direct` 2 · `linked` 3 · `unverified` 7.

- 대조 대상: 운영 JSON 12건 (`data/manual/*.json`) — **12건 전부 원문 확인**
- **12건 모두 `consultation_metadata`를 갖는다.**
- **화면에 iM뱅크 상담 후보로 나오는 것은 여전히 3건이다.** `linked`가 3건이 됐지만 새로 올라간 2건(dgsinbo-5·youth-1)은 **지역 한정 상품이라 `category=[]`로 제외**된다(§1-4 참조).
- 이 문서는 접수 가능 보장이 아니다. 확인일 이후 공고가 바뀔 수 있다.

### 등급 기준 (일관성)

| 근거의 성격 | 등급 | 해당 상품 |
|---|---|---|
| iM뱅크 **자사** 상품 페이지에 게시 | `direct` | imbank-1, imbank-2 |

### TLS 문제 해결 방법 (재현용)

`dgsinbo.or.kr`은 **중간 인증서를 보내지 않는 서버 설정 오류**다(leaf 인증서만 전송). 검증을 끄지 않고 서버가 빠뜨린 중간 인증서를 보충해 정식으로 검증했다.

```bash
openssl s_client -connect www.dgsinbo.or.kr:443 -servername www.dgsinbo.or.kr </dev/null \
  | openssl x509 -out leaf.pem
openssl x509 -in leaf.pem -noout -ext authorityInfoAccess   # CA Issuers URI 확인
curl -s -o inter.crt http://crt.sectigo.com/SectigoPublicServerAuthenticationCADVR36.crt
openssl x509 -inform DER -in inter.crt -out inter.pem
cat inter.pem /etc/ssl/certs/ca-certificates.crt > bundle.pem
curl --cacert bundle.pem "https://www.dgsinbo.or.kr/..."   # HTTP 200
```

`--insecure`는 쓰지 않았다. 상품 상세는 래퍼 페이지(`/page/10039/10043.tc?...&gdsNo=N`)에 서버 렌더되며, 내부 경로 `/guaranteegoods/detail.tc`를 직접 부르면 404다.

## 1-4. 근거를 확인해도 화면에 안 나오는 2건 — 지역 한정

`dgsinbo-5`(달성군)와 `youth-1`(북구)은 iM뱅크 취급 근거를 확보해 `linked`로 올렸지만 **상담 후보로 표시되지 않는다.** 운영 JSON에서 `category: []`로 인코딩돼 있는데, 이는 ‘해당 업종 없음 = 모두 탈락’을 뜻하며 §5-2가 *“`category=[]`로 제외된 지역 한정 상품은 계속 제외한다”*고 정한 처리다.

현재 매처는 **지역 조건을 보지 않는다**(업종·업력·연령만 본다). 그래서 지역 한정 상품을 넣으려면 지역이 맞지 않는 사용자에게도 보이게 되므로, 전부 제외하는 쪽을 택한 것이다.

**후속 과제**: 상품에 `region_codes`를 두고 사용자의 행정동·자치구와 대조하면 이 2건을 해당 지역 사용자에게만 보여줄 수 있다. 달성군·북구 예비창업자에게는 실제로 iM뱅크 취급이 확인된 상품이므로 가치가 크다. 이번 범위에는 넣지 않았다.

## 2. (해소됨) 아직 확인하지 못한 상품

모두 `consultation_metadata` 없음 = 미확인으로 남겼다.

**2026-09-18 3차 대조로 이 절은 비었다.** 12건 모두 원문을 확인했다.

다만 화면 문구 구분은 그대로 유지한다 — 원문을 본 적 없으면 “공식 원문을 아직 확인하지 못함”, 보았는데 은행이 안 적혀 있으면 “공식 원문에 취급 은행이 명시되지 않음”. 앞으로 새 상품을 추가할 때 이 구분이 다시 쓰인다.

**dgsinbo-4(금융기관 특별출연 협약보증)는 이름상 은행 협약이 있어 보였으나, 원문 확인 결과 취급은행이 ‘출연 금융기관’으로만 적혀 있어 `linked`로 올리지 않았다.** 모든 보증·정책자금에 iM뱅크 연결을 자동 부여하지 않는다(§5-2).

| 순위 | `bank_connection` | 화면 표시 | 판정 근거 |
|---|---|---|---|
| 1 | `direct` | iM뱅크에서 상담할 상품 | iM뱅크 자사 상품 페이지에 게시 |
| 2 | `linked` | 같은 그룹 | iM뱅크 연계 근거가 확인됨(자사 고시는 못 찾음) |
| 3 | `unverified` | 차선 후보 — iM뱅크 취급 미확인 | 취급 은행이 ‘시중은행’ 등으로만 표기되었거나, 원문을 아직 확인하지 못함 |
| — | `none` | 표시하지 않음 | 은행 취급 자체가 없다고 확인된 경우 |

이 등급이 기존 보증→은행→정책 정렬(`matcher._PRIORITY`)보다 **먼저** 적용된다. 같은 등급 안에서만 기존 정렬이 유지된다.

차선 후보에도 자격 조건(업종·업력·연령)은 동일하게 적용한다 — 차선이라고 느슨하게 보지 않는다. 차선 후보를 iM뱅크 상품처럼 설명하지 않으며, 카드에 ‘근거 미확인’ 배지와 직접 확인 안내를 함께 표시한다.
