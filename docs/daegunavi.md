## 1. 한 줄 정의

> **"서문시장 옆 이 자리에서 카페를 차리면, 내 돈 5천으로 몇 개월 버티고, 부족한 2천은 iM뱅크 어느 상품으로 메우는가"**

기존 상권분석 서비스는 "여기 위험해요"에서 끝난다. 우리는 **위험 진단 → 부족 자금 계산 → 금융상품 연결 → AI 분석 리포트 발급**까지, 창업자가 은행 창구에 들고 갈 수 있는 결과물을 만든다.

## 2. 확정된 방향 (브레인스토밍 결론)

- **컨셉**: A안 "창업 금융 네비게이터" 확정. 검토했던 B안(매출 증빙 체인)은 실매출 데이터 부재(DIP 센터 내 전용, 반출은 9/28 이후)로 제외하고 **로드맵 2단계로 흡수**. C안(기존 상인 대상 상권 신호 알림)은 **부가 기능/로드맵으로 흡수**.
- **AI 중심 확정**: 대회 주제가 AI **또는** 블록체인이므로 블록체인 없이 AI로 승부. 승부처는 ① 결정론 엔진(위험도·재무 계산) + LLM 해석 분리, ② Hybrid RAG 기반 금융상품 매칭·컨설팅. 리포트 해시 앵커링은 필수에서 제외하고 여력 시 선택 옵션(§10).
- **코드 전략**: 기존 Metabole(서울) 코드를 **이 저장소(cloud.localhostdaegu)로 이식**하고 대구 어댑터로 교체. 원천 저장소: `~/projects/cloud.beyondfacade` (백엔드 `apps/`: funding·rent·store·tobacco·news·rag·metric·ontology 등). Metabole은 자작 코드이며 타 대회 출품 이력 없음 → **재사용 제약 없음**.
- **트랙 매핑**: 공식 예시 ②청년 창업 매칭·시드 금융 연결 + ③골목상권 데이터 기반 AI 컨설팅 동시 커버.

## 4. 사용자 흐름 — "한 문장 깔때기"

진입이 지도 핀이 아니라 **채팅 한 문장**이다. 업종·예산이 첫 문장에서 확보되므로 뒤 단계가 가벼워지고, 전체가 "질문 → 진단 → 보완 → 결론" 깔때기가 된다.

```
⓪ 랜딩            입력창 하나 (redoceanmap 스타일). "무엇을 알아볼까요?"
                   예시 칩: 서문시장 근처 카페 · 동성로에 미용실 · 예산 5천으로 뭐 하지?
                   우회로: "지도에서 직접 둘러보기" 링크

① 의도 분기        한 입력창이 세 질문 유형을 수용 — 전부 같은 지도 무대에 착지
                   A 정방향(지역+업종): "들안길에 카페, 예산 5천"
                     → 해당 폴리곤 줌인 + 그 업종 위험도 진단
                   B 업종 미정(지역만): "서문시장 근처에서 장사하고 싶은데"
                     → 폴리곤 줌인 + 업종별 위험도 랭킹 ("피해야 할 업종" 경고가 주인공)
                   C 지역 미정(예산/업종만): "예산 5천이면 뭐 할 수 있어?"
                     → 대구 전역 코로플레스 + 예산 내 업종 역매칭(공정위 창업비용) 또는 추천 행정동
                   ※ 추출은 결정론 우선: 행정동 사전 + 랜드마크 별칭(서문시장→대신동,
                     들안길→상동·중동, 안지랑→대명동…) + 업종 동의어. 자유문만 LLM 보조.
                     정보 부족 시 칩으로 되물음.

② 무대: 지도+진단   Metabole map-explorer(폴리곤 코로플레스) + 진단 패널
                   위험도 종합점수 → 경쟁밀도(300/500m) → 개폐업 시계열
                   → 전통시장·먹거리골목·대규모점포 반경 배지 → 임대료 수준
                   A유형이면 "이 업종 68점 — 진입 주의" + 대안 업종 2개(B로직 재사용)
                   옆 폴리곤 클릭으로 즉시 동네 비교

③ 보완 입력        폼이 아니라 "프리필된 확인": 예산(채팅에서)·월세(R-ONE 평균)·
                   원가율(업종 벤치마크) 자동 채움 — 빈 필수값만 입력(보증금·인테리어·희망대출)

④ 결론 (한 화면)    비관·기준·낙관 3시나리오 → "BEP 16개월 · Runway 9.4개월 · 부족 자금 2,000만"
                   → Funding Gap 숫자가 그대로 헤드라인이 되어
                   "부족한 2,000만, 이렇게 메울 수 있어요"
                   ① 대구신보 보증 → ② iM뱅크 대출 → ③ 정책자금 순 매칭 카드
                   → [AI 종합 리포트 생성] (SSE 진행 패널) → 리포트 뷰 → PDF

⑤ 루프백           결과에서 원클릭 재실행: "예산 7천으로" / "옆 동네로" / "업종 바꿔서"
                   → ②로 복귀 (URL 상태 교체). 상주형 채팅 도입 시 이 명령들이 대화 명령이 됨
```

- ②의 위험도 스코어링과 ④의 재무 계산은 전부 결정론 코드. LLM(RAG)은 의도 추출 보조와 결과 해석·근거·대안 제안만 담당한다.
- 채팅 UX 깊이: **관문형(채팅→URL 상태→지도)으로 확실히 구현**하고, 여력 시 도킹 채팅(상주형)으로 후속 질문 1~2개 명령을 스트레치 — 상태를 전부 URL에 담아 구조 변경 없이 업그레이드 가능.
- 은행 서사: Funding Gap → 금융상품 매칭이 화면 동선으로 직결되어 "분석 → 대출 리드" 흐름을 증명.

## 5. 핵심 기능

### 5.1 상권 진단 (AI 컨설팅)
- 인허가 7업종 개폐업 시계열(2017~) → 폐업률·생존율·신규진입률
- 상가정보 → 반경 300m/500m 경쟁밀도, 업종 다양성
- 대구 특화 파생변수: **전통시장 반경 500m**(서문·칠성 등), **먹거리골목 클러스터**(안지랑곱창·평화시장닭똥집·들안길), 대규모점포 반경(상권 흡수 위험), 코로나 1차 대유행(2020.2~3 대구) 더미변수
- 위험도 산식(부트캠프 과제 계승): `위험도 = 경쟁밀도정규화×0.3 + 폐업률×0.3 + 매출감소율×0.2 + 프랜차이즈포화도×0.2`

### 5.2 재무 시뮬레이션 (Finance Engine — 결정론)
- CAPEX = 보증금 + 권리금 + 인테리어 + 설비 / OPEX = 월세 + 이자 + 보험 + 인건비
- 산출: 예상 BEP, Runway(개월), **Funding Gap(부족 자금)**, 투자 회수기간
- ECOS 기준금리·대출금리로 금리 +1%p/+2%p 스트레스 테스트
- 업종별 원가율 벤치마크(소상공인 실태조사) + 사용자 입력 우선

### 5.3 금융상품 매칭 (시드 금융 연결)
- 원천: iM뱅크 소상공인 대출(수기 JSON) · 대구신용보증재단 보증(수기 JSON) · 기업마당·온통청년 대구 필터 · 대구 청년창업 지원사업 · 대구로페이 가맹 인센티브
- 로직: 분석 결과(위험등급·업력·업종·Funding Gap) → 상품 `target` 조건 필터 → 우선순위(보증 연계 → 은행 상품 → 정책자금) 정렬
- **은행 수익모델 직결**: 분석 결과가 iM뱅크 대출 상담 리드로 이어지는 구조
- 금리 실데이터 보강(P1): 금감원 "금융상품 한눈에" 오픈API로 iM뱅크 포함 은행권 공시 금리 서빙 — 할루시네이션 방지 (apilist §10-1). iM뱅크 자체 오픈API는 제휴 심사 필요 → 로드맵 기재

### 5.4 AI 리포트 (Hybrid RAG)
- 입력: Feature Store 결과 + Finance Engine 결과 + 정책/금융 RAG 문서
- 출력: 왜 위험한지 / 어떤 변수가 문제인지 / 무엇을 바꾸면 되는지 / 대체 입지 / 자금조달 경로
- 시스템 프롬프트의 지역 컨텍스트는 `RegionConfig`에서 주입 (서울 문구 잔존 금지)

### 5.5 (선택) 블록체인 리포트 앵커링 — 여력 시에만
- 분석 리포트의 SHA-256 해시 + 타임스탬프를 체인에 기록(`POST /report/anchor`) → 제3자(은행 심사역)가 리포트 진위·시점 검증
- D-2까지 핵심 기능이 안정된 경우에만 착수. 미구현 시 제안서 로드맵에만 기재
